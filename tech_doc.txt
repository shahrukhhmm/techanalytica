Product Requirements Document
1. Product Overview
Product Name:
 Techanalytica
 
Product Type:
 B2B AI tools directory + editorial + vendor marketplace
 
Core Purpose:
 Help professionals discover, evaluate, and understand AI tools for work
 
Secondary Purpose:
 Provide visibility + distribution channels to AI vendors
 
V1 Lens:
 Marketplace + media hybrid with monetization
2. Problem Statement
Businesses want to adopt AI tools but discovery is fragmented, hype-driven, and shallow.
 Professionals struggle to filter through thousands of tools that feel similar with unclear differentiation.
Vendors struggle to get qualified visibility, especially newer or niche AI tools.
 Current ecosystems (Futurepedia, Toolify, Product Hunt) lack depth, credibility, editorial analysis, and structured buyer-assistance.
3. Value Proposition
For buyers / professionals:
Discover relevant AI tools quickly
Compare by category &amp; industry
Understand use cases and pricing
Benefit from editorial context (blogs, insights)
Shorten AI adoption decision cycles
For vendors:
Gain visibility
Acquire credibility via structured listings
Access performance insights (analytics)
Purchase sponsored placements
Reach early adopters + enterprise buyers
4. Target Users / Personas
(1) Professional Buyers
Examples:
IT leaders
Product teams
Marketing &amp; Sales leaders
Ops &amp; CX teams
Founders &amp; startup teams
Needs:
 clarity, trust, categorization, pricing, use-cases
(2) Vendors (AI Tool Creators)
Types:
PLG SaaS startups
Enterprise AI vendors
Consulting/solution firms

3. Functional Requirements
3.1 Listings
System must allow:
Creation (admin, vendor submit)
Editing (vendor after claim)
Publishing (admin)
Featuring (admin, paid)
Categorization
Industry tagging
Media uploads (logo, screenshots)
Video embeds
Pricing data
Configurable CTA (1 type per listing)
Status tracking
Listing Status States
Draft
Pending Review
Approved / Published
Rejected
Archived
3.2 Vendor Claim Workflow
System must allow:
Vendor to initiate claim
Admin to verify &amp; approve
Convert listing to vendor-owned
Post-claim instant editing rights
Claim Status
Unclaimed
Claim Pending
Claimed
3.3 Vendor Submission Workflow
System must allow:
Vendor to create a new listing
Submit for review
Admin to approve/reject
Submission States
Draft
Pending
Approved
Rejected
3.4 Editing Rules
After claim:
Vendor edits go live instantly
System enforces limits (character count, screenshot count, CTA type, pricing fields)
Admin overrides:
Admin may suspend or rollback listing
3.5 Categories &amp; Industries
Categories:
Defined by business function (Marketing, Sales, Finance, etc.)
 Industries:
Overlay tags (Healthcare, Retail, Manufacturing, etc.)
System supports:
Many-to-many relationships
3.6 Search &amp; Filtering
System must allow:
Keyword search
Category filter
Industry filter
Sorting by ranking
Ranking = hybrid (editorial + sponsored + recency)
3.7 CTA Behavior
CTA types (V1):
Website
Sign Up
Try Free
Demo
Contact Sales
Rules:
1 CTA per listing
CTA requires URL
CTA click triggers analytics event
3.8 Pricing Fields
System supports:
Starting price (free text)
Quote / Custom pricing (toggle)
Tier names (optional V1)
Trial availability (boolean)
3.9 Sponsored Placements
Duration-based sponsorship
 Placement types:
Category Featured
Homepage Featured
Newsletter/Blog Featured
System must allow:
Purchase flow
Admin assign or auto assign
Expiration management
Renewal reminders
Billing &amp; invoicing
3.10 Vendor Dashboard
Dashboard must show:
Listing status
Upgrade options
Sponsorship options
Billing &amp; invoices
Analytics (paid)
Views
CTA clicks
3.11 Analytics
V1 analytics include:
Page views (unique)
CTA click-outs
Analytics locked to paid tier
Events stored:
tool_id
vendor_id
event_type
timestamp
referrer (optional V2)
3.12 CMS Requirements
CMS must manage:
Listings
Vendors
Categories
Industries
Sponsored placements
Homepage blocks
Blogs
SEO fields
Media assets
Pricing tiers
CMS must support:
Draft / Publish states
Scheduled publish (blogs optional)
Manual featuring
3.13 Blog / Editorial
System must support:
Blog listing page
Blog detail page
Tags (optional)
Categories (optional)
SEO fields (slug, title, meta, OG)
Content types:
Editorial
Lists
Comparisons
Insights

✔ Vendor (supply side — the one who pays)
 ✔ Buyer / Visitor (demand side — the one who reads + clicks)
 ✔ Admin (ops + approvals + revenue control)
 ✔ Editor (content + polish)

Visibility + Credibility + Traffic + Distribution

Discovers Techanalytica →
Browses listings →
Thinks: “why isn’t my product here?” →
Sign-up (Google or Email) →
Dashboard →
Search own product →
Either:
  → Claim (if exists)
  OR
  → Submit (if not found) →
Approval →
Edit Profile →
Sees premium fields locked →
Upgrades to unlock →
Considers sponsorship →
Views analytics (paid) →
Repeats sponsorship/renewals →
Advocates for more visibility

Post-claim
 (ownership psychology)
Post-publication
 (FOMO vs peers)
Analytics preview
 (prove ROI)
Category competition
 (rank anxiety)
Newsletter/blog features
 (ego + reach)
Marketplace science: vendors convert on 
status + scarcity + competition

🧬 STATE MACHINES (By Core Entities)
These define how the system behaves. Very important for dev &amp; workflow consistency.
1. LISTING STATE MACHINE
States:
Draft → Pending Approval → Published → Archived
Triggers:
 ✔ Draft created (vendor or admin)
 ✔ Submit for approval (vendor)
 ✔ Approve (admin)
 ✔ Reject (admin)
 ✔ Archive (admin)
 ✔ Edit (vendor) → live instant (your rule)
2. CLAIM STATE MACHINE
States:
Unclaimed → Claim Pending → Claimed
Transitions:
Claim Pending → Rejected (fallback loop to Unclaimed)
Verification rules (soft):
 ✔ Verified email domain
 ✔ Company match (optional)
 ✔ Role/Title match (optional)
3. SUBMISSION STATE MACHINE
States:
Draft → Pending → Approved → Rejected
Note:
Approved → triggers Published in Listing SM
4. SPONSORSHIP STATE MACHINE
Since you chose 
duration-based
, state is time-bound:
States:
Inactive → Active → Expired
Transitions:
Purchase → Active → (time) → Expired → Renew
Renewal triggers (notifications):
T minus 7 days
T minus 1 day
Expired notification
Renewal upsell opportunity
5. BILLING STATE MACHINE
Stripe handles 80% of this, but logically:
States:
Pending → Paid → Failed → Refunded
Possible extension (V2):
Recurring subscriptions
For V1:
 ✔ One-off upgrades
 ✔ One-off sponsorships
6. ANALYTICS EVENT STATE MACHINE
Analytics is event-based, not persistent state-based:
Event Types (V1):
view
cta_click
Stored with:
timestamp
tool_id
vendor_id
session_id (optional)
referrer (optional)
device (optional V2)
Analytics unlock triggers paywall:
Analytics Locked → Upgrade → Analytics Unlocked
📌 CONNECTING STATE MACHINES (Marketplace View)
This is how they interact (important for dev):
Submission.Approved → Listing.Published
Claim.Approved → Listing.Owner = Vendor
Sponsorship.Active → Ranking Boost
Sponsorship.Expired → Ranking Revert
Upgrade.Paid → Listing.FieldsUnlocked
Analytics.Paid → DashboardMetricsUnlocked
That’s the whole monetization logic encoded in 6 lines.
 This is 
exactly how Product Hunt + Crunchbase PLG revenue works.
